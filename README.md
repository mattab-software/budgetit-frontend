# budgetit-frontend

The Angular PWA for BudgetIt, a company budget app. Built with Angular 22 (standalone components, signals, zoneless), Angular Material and a service worker.

- **Backend:** [budgetit-backend](https://github.com/mattab-software/budgetit-backend), Spring Boot. It must be running for anything beyond the login page.
- **[Roadmap](https://github.com/mattab-software/budgetit-backend/blob/main/docs/ROADMAP.md)** (in the backend repo): architecture, API, the auth contract and the progress checklist.

## Run locally

1. Start the backend (see its README). It listens on http://localhost:8080.
2. Start the frontend:

   ```bash
   npm install
   npm start
   ```

3. Open http://localhost:4200 and sign in with the dev admin from the backend README.

## Commands

| Command | What it does |
|---|---|
| `npm start` | Dev server on http://localhost:4200. It proxies `/api` to the backend on `:8080` (see `proxy.conf.json`). |
| `npm test` | Unit tests (Vitest). Add `-- --watch=false` for a single run. |
| `npm run build` | Production build into `dist/frontend/browser`, including the service worker. |
| `npm run gen:api` | Generates typed API services and models into `src/app/api` from the running backend's `/v3/api-docs`. Needs `java` on PATH. Run it whenever backend DTOs or endpoints change, and commit the result. |
| `npx ng generate component features/foo/foo-dialog` | Scaffolds a component. |

The service worker only runs in production builds. To try it locally, serve `dist/frontend/browser` with any static server on `localhost`.

## Structure

```
src/app/
├─ core/                 app-wide singletons
│  ├─ auth/              AuthService (current user signal), guards, auth DTOs
│  ├─ http/              error interceptor (401 → /login, other errors → snackbar)
│  └─ pwa/               "new version available" prompt
├─ layout/shell.*        sidenav + toolbar around every signed-in page
├─ features/<feature>/   one folder per screen, lazy-loaded from app.routes.ts
├─ shared/               small reusable pieces (page header, YearMonth helpers)
└─ api/                  generated by `npm run gen:api` (do not edit by hand)
```

## Adding a screen (the usual pattern)

1. Create a component in `features/<name>/`. Inject the generated `XxxService` from `src/app/api` to load data.
2. Hold page state in `signal()`s, and derive values with `computed()`.
3. Register it in `app.routes.ts` with `loadComponent`. Add `canActivate: [roleGuard('ADMIN')]` if it needs a role.
4. Add a nav entry in `layout/shell.ts` if it belongs in the sidebar.
